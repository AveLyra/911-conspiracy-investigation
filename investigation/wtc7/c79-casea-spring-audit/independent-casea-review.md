## Important non-equivalences and remaining gaps

1. **Master alias scope:** the root newly re-extracts all selected master
   shell rows and checks their frozen source/connectivity/PID aliases. My
   independent pass freshly re-extracts all selected master-vertex
   coordinates and every CaseA-listed shell, but uses the frozen master
   alias metadata for the unlisted aliases. Consequently the common 742
   membership/version-identity results agree; full nonlisted master-shell
   connectivity is **not** a new dual raw-source extraction. The independent
   negative membership follows the complete freshly parsed CaseA shell set,
   not a second parsing of the unlisted master shell's connectivity.
2. **Independent-only fields:** stored raw numeric-row hashes/formats,
   thickness values/card locators, NODE constraint slots and orientation
   fields have no retained counterpart in the root common record schema.
   Their existence and parser validation must not be described as dual
   numerical reproduction. Candidate-pair-row counts, hashed unknown-token
   counts and expanded relation provenance also have no root counterpart.
3. **Root-only fields:** spring card/curve inventory is outside Arm A's
   independent source extraction. Equality between the root repeats does
   not close that separate verification or supply spring-law semantics.
4. **Parser scope:** both implementations reject duplicate typed element
   identities; the root checks global NODE duplicates, while my duplicate
   NODE check is limited to selected nodes. Root list parsing strips inline
   comments; mine rejects inline text. They nevertheless reached the same
   pinned complete streams and numeric products on the supplied inputs.
5. **Geometric and physical limits:** both inherit the same frozen exact
   candidate classification and source snapshots. Independent coding does
   not create independent historical evidence, repair missing run states,
   or validate the antecedent geometry as an initialized solver contact.
