## Result and scientific consequence

A public [architectural catalog](https://flickr.com/photos/52125362@N08/albums/72157648567993373)
supplies a specific new lead: **WTCI-000120-I.PDF**, attributed by its uploader
to Emery Roth and FOIA12-178. It is not yet an authenticated original drawing
set, a verified match to NIST's Roth1985 citation, or an identified north-
elevation/louver sheet. The title-page metadata suggests mixed issue/revision
dates; original title blocks and a release crosswalk are needed.

This narrows the existing architectural-family/detail lead to a specific
publisher catalog, claimed source file and title-sheet item. **It supplies no new geometric,
motion, force or causal result.** None of its drawing images has been inspected.
The root and second reader viewed the same uploader's metadata; agreement is
review corroboration, not independent historical provenance.

The target remains the west-end upper-louver corner used in the
[Camera3 feature study](../camera3-facade-feature/report.md): its material,
attachment, slab offset and depth must be identified before imposing those
constraints on video measurements. The prior common apparent motion remains
positive evidence; failure to identify the detail does not establish arbitrary
motion or erase that observation. Even a correct drawing would need a
revision/installed-condition and image-feature join. It would not alone give
the Camera2 body/COM bound required by the [force test](../finite-interval-force/report.md).

## Tool defect, correction and inferential limits

Independent synthetic testing exposed a real defect: the original archive
guard could admit ZIP64 metadata with ordinary legacy EOCD fields and thereby
miss a larger effective directory size. The [correction record](GUARD-CORRECTION.md)
preserves the original code and outputs and specifies the bounded repair.
The independent current-input reader had already rejected preceding ZIP64
locators. It reproduced the finite historical-input coverage using that guard.

This is not a hardened hostile-archive service: malformed entry-count
declarations are checked against parsed records afterward, and unknown file
aliases cannot be recognized solely from a filename. Actual current input
sizes/counts, independent reconstruction, revised runs and synthetic tests
are distinct verification layers. See the final [validation record](validation.md)
for what ran; no passing locator test validates structural mechanics.
