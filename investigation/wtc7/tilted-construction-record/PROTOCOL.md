## Pre-execution clarification from independent protocol review

Added before any historical source read; initial protocol prefix SHA256 was
`0c020c6e7ee7d81b37c3c0777ad92ecc899ef539992e0e50dcfdc8eedd28e990`.
These clarify representation/coverage, not a response to historical results.

- "Complete XML structure" means every parsed element and every attribute.
  Unknown tag/attribute names and attribute values are hashed; only `object`
  and `property` tag names, `name`, `class`, `type` attribute names and the
  already-listed technical values may have plaintext labels. Attribute names
  alone never authorize their values. Preserve namespace-containing names as
  unknown hashed identities rather than dropping them.
- Preserve node.text and node.tail separately as hashed parsed text segments,
  distinguishing absent, empty, whitespace-only and nonempty. For an owner's
  property, also report immediate textual content as node.text plus each
  element-child's tail, with count/hash/state; this prevents mixed content
  after children from disappearing. It is parsed character data, not the
  original XML byte substring or serialized lexical spelling.
- "Leaf string" means an element with literal type=`string` and no element
  children. Separately list all structured type=`string` nodes with their
  paths/shapes; they are not silently ignored or called empty descriptions.
  Text-bearing elements of other types remain in the complete element ledger,
  not in the string-leaf subset.
- The existing ElementTree parser excludes XML comments and processing
  instructions. This unit expressly excludes those from its element inventory
  and any negative-content conclusion; it is not an all-XML-token or complete
  possible-documentation search. DOCTYPE/entity declarations remain rejected.
  Independent parsing must compare the same declared element/text semantics,
  including CDATA/text coalescence, without executing instructions.
