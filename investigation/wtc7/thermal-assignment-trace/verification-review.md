## Method and prospective checks

The standard-library reader hashes complete streams while admitting required
typed cards only. Its first master-file pass reconstructs PID179 shell vertices
from connectivity, independently of a guessed node range. A second geometry
pass joins only selected coordinates and incident elements in SRC119–121;
an SRC118 pass preserves every selected assignment and computes the full-file
ordering-run partition. No whole node-coordinate array is stored or output.
Unselected node IDs are read to locate the chosen coordinates, but unselected
coordinate fields are not parsed or validated; this is not whole-mesh QA.

Shell connectivity and thickness continuations are separate. Incidence counts
deduplicate repeated physical node IDs within each element. Beams use N1/N2,
not their N3 orientation reference; grounded discrete N2=0 is omitted, and
its VID is not a node. Outside-include part IDs are offset by1000, node IDs
unchanged. Both documented solid layouts have synthetic coverage, while
unsupported required geometry variants fail with safe codes.

All retained noninteger source values are parsed through Decimal and serialized
as canonical exact decimal strings, not rounded values or chosen temperatures.
Integers and source locators are exact. A strict NID decrease begins a new
ordering run; equality stays in the current run. Runs retain global row and
physical-line endpoints, first/last NID and row count. A run has no assumed
meaning as elapsed time, source batch, floor, file or transfer algorithm.

Per-node assignment summaries distinguish row count, distinct (TS,TB,LCID)
tuples, equal duplicate rows, and adjacent equal/unequal assignments in that
node's retained source order. Rows beyond one per node are not synonymous
with equal duplicates. The categories are unassigned, single, repeated_equal
and repeated_unequal. Missing assignment, coordinate or incidence remains an
explicit unmatched result. Per-part node-element incidence totals are not
counts of unique elements or independent temperature observations.

Caps are512MiB uncompressed/source,16384bytes/line,2000selectedIDs,
10000ordering runs,20000selected rows and768MiB peak process memory.
Receipt code/hash/EOF/pins are retained and outputs are create-only. Failure
codes never include a raw offending line or arbitrary exception text.
