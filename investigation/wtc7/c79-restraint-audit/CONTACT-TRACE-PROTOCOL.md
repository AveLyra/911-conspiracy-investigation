# Contact and set membership extension

September 13, 2026; prospective for the new typed-set/contact joins. The
original direct-incidence protocol and frozen outputs remain unchanged.
Root already knows the direct graph counts and inspected the first metadata
inventory, including six contact blocks and two node-list blocks. Earlier
inventory locates six segment sets. This is not a blind discovery protocol.

## Why extend the graph

Only exact shared-node connections were reconstructed in the first test.
The identified contact variants include ID before OFFSET. The first metadata
reader deliberately hashed those unrecognized variants and did not parse their
textual ID headings; it did not claim those headings were absent. M971 physical
363–364 permits option reordering; 366–367 fixes the ID-heading card before
ordinary cards. These are distinct parser and physical-method questions.

## Declared extraction

Read the same three hash-pinned geometry streams to EOF, without running them.
Admit exactly the observed CONTACT_TIED_SHELL_EDGE_TO_SURFACE_ID_OFFSET,
CONTACT_TIED_SURFACE_TO_SURFACE_ID_OFFSET and
CONTACT_AUTOMATIC_SINGLE_SURFACE_ID variants. Parse only the numeric CID from
the heading card, hashing its text; retain every following numeric card and
blank position without interpreting unreviewed optional-card defaults.

Parse SET_NODE_LIST, SET_SEGMENT and SET_PART_LIST header/membership records
separately. Preserve set namespaces, line pins, duplicate membership counts,
total rows and unique node/part counts. Segment fields 1–4 are node IDs; fields
5–8 are attributes, not additional nodes. Repeated N3/N4 can designate a
triangle. Do not flatten segment orientation or infer element IDs from node
numbers. Unsupported variants fail rather than silently entering these sets.

Join each set to the frozen 873-node / PID179 seed. Retain all intersecting
node-list entries and segment records, ordered nodes, attributes, all matched
seed IDs and counts. Identify segment records whose complete ordered vertex
list matches a seed shell, and separately records with the same unordered node
set. Neither matching rule is a contact-pair selection algorithm.

Resolve contact selection fields through their explicit type: SSTYP4 is a
node set, SSTYP/MSTYP0 is a segment set and SSTYP2 is a part set under the
inspected M971 Card1 schema. Zero master ID in single-surface contact is not a
missing master set. Record the relevant source input rows; do not infer active
slave/master pairs, initialize contact, invent penalty stiffness, interpret
zero options as zero force or activate candidate damage lists.

Controls cover ID placement/free-format header parsing, header-versus-member
separation, node/segment/part namespaces, repeated membership, triangle slots,
attributes-versus-IDs, missing references, unknown variants and no intersection.
Two create-only passes must reproduce all scientific fields. Independent
source extraction of the scoped joins is required before the result is
called independently verified; reusing the first result is not independent.

## Scientific ceiling

M971 physical364 describes OFFSET tied contacts as penalty-based transfer,
not identical-node rigid links. Physical402–403 describes proximity and
thickness/geometry dependencies and untied-node warnings. These rules require
applicable executable/version checks; input membership is not proof a node
was successfully tied, remained tied after damage, or supplied historical
restraint. M971's source schema is not an authenticated historical run.

Keep the per-floor/direction report matrix separate from the model-coordinate
input map until their crosswalk is actually supported. No physics/cause/intent
or legal finding, solver execution, raw/main edits, source transfer or outreach.
