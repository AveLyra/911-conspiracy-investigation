## What a row set means

Each reader separately records, for every target column, an explicit sorted
set of core rows, fringe rows, and any unresolved/gap/truncation judgment.
Core means cells visually attributable to the local dark stroke using shape,
context and raw values. Fringe means plausible edge/antialiasing/compression
cells whose attribution is uncertain. These are reader annotations, not
ground truth, an automatic intensity/color predicate, or a calibrated
enclosure of a pre-raster centerline. Empty core is not zero load, absent
curve or a verified dash gap. No inferred centerline is supplied.

Do not reuse the failed color classifier, choose a new scalar cutoff, bridge
dash gaps, connect crossing branches, select by model difference, or infer
continuity outside the finite target. Store multiple row runs if present;
do not fill holes by reducing them to a bounding box. Mark any candidate
ink reaching the target's boundaries. A continuing solid line truncated by
the selected columns is not a physical endpoint. An individual dash is not
the entire dashed curve's supported domain.

The two readers freeze their files before reading each other's annotations.
Each records source/protocol/raw-context hashes, image coverage, actual cues,
alternatives and limits. Equal responses can reflect shared interpretation;
they cannot establish original line placement or centerline uncertainty.

## Reconciliation and acceptance

Only after both freezes, compare core/core and core-plus-fringe row sets
column by column. Preserve both original records, exact intersections,
unions and symmetric differences; list each disagreement without replacing
either response. A union is a reader-ambiguity envelope, not a confidence
interval or validated original-curve envelope. Core/fringe disagreements
remain distinguishable from differences in the outer annotated set.

Use a small local validation/reconciliation script, not a new framework.

These tests verify recording/arithmetic, not the correctness of annotation.
