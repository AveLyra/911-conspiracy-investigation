        Modified-Huffman codebook
        For suffix width n > 0, its first bit is sign s and its remaining bits are unsigned magnitude m. With category start a, the
        unsigned 12-bit difference is a + m when s = 0 and 4096 - a - m when s = 1. A baseline assigns the difference directly; a
        delta adds it to the preceding same-stream word modulo 4096.
         Prefix                    Category start a                  Suffix width n
         0                         0                                 0

         110                       3                                 3
         1110                      7                                 4
         111100                    15                                5

         1111010                   63                                7
         111111                    127                               8
         1111101                   255                               9

         111101110                 1023                              11

             2. Page order, frame boundaries and partial data
             Terminology: a page here is 128 bytes; a bank is 64 KiB; a bank pair is 128 KiB. These sizes distinguish hardware
             pages from the larger envelope units used in earlier summaries.
             Source-derived read order
             The reader scans bank-pair headers backward, identifies the erased pair, and starts the ring after it. For these bytes, the
             payload begins at offset 170 and logical page 0 maps to physical 128-byte page 30,720. Pairs are visited 30 through
             191, then 0 through 28; erased pair 29 is excluded. This is an implementation-supported read order, not an
             independently established wall clock.
             Stream 0 takes the first bank of each pair; stream 1 takes the second. The first two 128-byte pages of each bank are
             skipped. Entirely FF pages are skipped, without inserting zero-valued words. Each retained page contributes 1,013 bits:
             16-bit words are loaded little-endian, then consumed most-significant bit first. The last 11 page bits are not used by this
             decoder.
             Frame state and chronology
             A baseline begins with 1000 and a 16-bit compressed-frame counter, followed by 1,020 Huffman-coded words. A delta
             begins with 0, advances that stream counter by two and updates its preceding frame. The 1,020 words correspond to
             SF1-SF4, W2-W256; W1 is absent. The stored 16-bit FEFE delimiter is recognized only at a new 16-bit boundary while
             waiting for an end marker, excluding page word 63. Padding before that delimiter must be all ones.
             The author merges streams using the modular comparison ((candidate - current) & 0x8000). This audit validates the final
             bounded interval directly, where counters run 49176-50473 without a wrap. Periodic baselines duplicate the current
             frame and are not extra time steps.
               Handling decision                 Audit treatment
               Baseline suppression              The author suppresses all baselines, including the first in each stream. This audit retains them as
                                                 evidence, then removes verified periodic duplicates from the merged interval. It does not claim identical
                                                 GUI output.
               Unsupported / bad records         All are flagged in diagnostic metadata. The selected interval contains no such records. They are not
                                                 accepted as engineering observations.
               End-of-input behavior             Reads are bounded before leaving the eligible ring. The original after-increment bound and unbounded
                                                 empty-page loop are not copied as unsafe EOF behavior.
               Partial-frame cutoff              Both completed-symbol count and the original last-zero-bit heuristic are recorded. No uncompleted
                                                 symbol is promoted to a usable selected word.
               Partial final frame               Compressed counter 50474 has 1,007 completed words and a sync-loss symbol. It and subsequent
                                                 unsupported records are excluded from this reconciliation.
             The author ignores bad-page maps and Hamming/parity validation; this audit likewise does not certify those integrity fields. ASC-TRT99-007
             figure 4.2-2 supports the general two-stream memory layout, but not this exact codebook or all implementation details. Its apparent data-page
             label differs from the code start; that ambiguity is retained.

            3. Ordering validated against stored native sync
            The compressed decoder does not recover W1 sync words. The author GUI synthesizes a subframe identifier, and the
            separate decompressor inserts standard sync constants. Testing those inserted values would be circular. This audit
            instead reads native uncompressed bits immediately before the final segment's first baseline.
            Manufacturer documentation supplies the expected sequence 0x247, 0x5B8, 0xA47, 0xDB8, with ARINC word bits
            transmitted LSB first. Those values are actually present at 3,072-bit intervals in the retained page stream. This native
            word-bit direction is distinct from the recorder storage-bit order. [S3]
              Native subframe     Observed W1         File byte / bit (LSB0)                    Logical page / data bit
              SF1                 0x247               2,783,100 / 1                             187629 / 670
              SF2                 0x5B8               2,783,488 / 0                             187632 / 703
              SF3                 0xA47               2,783,879 / 7                             187635 / 736
              SF4                 0xDB8               2,784,267 / 6                             187638 / 769
            The native SF4 is partial. The next aligned FEFE storage word is at byte 2,784,572. The following actual header begins
            at byte 2,784,575, bit 7: 1000 plus compressed counter 49176. Its payload starts at byte 2,784,577, bit 3. All offsets are
            zero-based.
            Native SF1 W256 is 3 and native SF3 W256 has cycle nibble 0. The following baseline decodes to raw frame counter 4
            and cycle nibble 1. Stream 1 then supplies counter 5 / cycle 2. These primary-document-addressed fields connect the
            observed native phase to the compressed sequence. This is a local ordering check; the native and following

            Exact decimal equality was required, with zero numerical tolerance. These sampled conversions fall exactly on the CSV
            display resolution. No calibration tolerance, interpolation, phase fitting or physical trajectory argument was used.
            Concrete example
            At aircraft frame 1301 / SF4, W29 = 0x004 and W30 = 0x2B4. The coarse field is 1; the seven-bit fine field is 45. Boeing
            therefore gives 128 + 45 = 173 ft, exactly CSV E37806. Retaining the overlapping fine bits gives 128 + 173 = 301 ft. The
            128-ft difference is now demonstrated on decoded words, rather than an inverted export example.
            At the same frame / SF4, W147 = 0xBCF = 3023; 3023 / 100 = 30.23 inHg, exactly CH37806. Its nibbles B, C, F cannot
            be literal decimal digits.

               Index conventions
               Streams, decoder record IDs, physical file byte offsets and page indices are zero-based. Subframe, word and channel
               bit numbers are one-based; channel bit 1 is the numeric LSB. File bit locators explicitly use LSB0 within the actual byte.

               documented page iterator.

               one-based physical file rows and standard spreadsheet column letters. Every parsed source CSV record occupies one
               physical line. Example E37806 means physical line 37806, column 5; CH37806 means the same line, column 86.
